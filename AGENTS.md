# AGENTS.md

Instructions for AI coding agents working in this repository. Read this before making
changes; it explains what the project is, how it is wired, and which rules keep it healthy.

## What this project is

A static web catalog of every hero and suit from the Minecraft mod **Fisk's Superheroes
(FiskHeroes) 2.4.0** (1.7.10): **535 heroes in 21 packs**. The same codebase serves as a
regular website and a **Telegram Mini App**.

- **No backend, no database, no build step, no npm/frameworks.** `index.html` is one
  self-contained vanilla HTML/CSS/JS file. Do not introduce build tooling.
- Styling is the **VS Code Dark+** palette (CSS variables in `:root`).
- UI is fully localized in **8 languages** (ru, en, uk, es, ko, ja, fr, de) via the
  `I18N` object in `index.html`. Any user-visible string you add must be translated into
  **all 8** languages, not just English/Russian.
- All counters/labels are computed from JSON at runtime — never hardcode hero/pack counts
  in UI code.

## Hard rules

1. **Never `git push` without an explicit user request in the current conversation.**
   The repo is connected to Cloudflare (Workers static assets): pushing to `main`
   deploys to production immediately. Work is delivered as local commits.
2. **Commits use the repo-local identity** already configured in `.git/config`
   (`git config user.name` / `user.email` — never override, change or copy it elsewhere)
   and are GPG-signed through the machine-global `commit.gpgsign` key. Every commit in
   this repo's history uses it; keep it that way and verify with
   `git log --format='%an <%ae> sig:%G?'` after committing.
3. **Never commit game files or Mojang assets**: mod jar, heropacks (`*.zip` is
   gitignored for this reason), vanilla Minecraft textures. Everything under
   `assets/heroes/` is either generated by our tools, downloaded from
   fiskheroes.fandom.com, or procedural pixel art (the default player head).
4. **Determinism**: every script in `tools/` must produce byte-identical output when
   re-run on the same inputs. No timestamps in outputs, no randomness, stable sort order.
5. **Paths are never hardcoded** in scripts. Game install location is passed via
   `--mc-root` (env `MC_ROOT`), repo location via `--repo`, wiki cache via
   `--wiki-research` (env `WIKI_RESEARCH`).
6. Keep the docs honest: when behavior or numbers change, update `README.md`,
   `docs/DEPLOYMENT.md` and `docs/scripts/README.md` in the same commit.

## Preview images: how they are made

Three independent sources, canonical priority **wiki render > custom model render >
texture front view** (merged by `tools/wiki_previews.py` into `heroes_list.json`):

1. **Wiki renders** (`assets/heroes/wiki/`, 56) — 3D renders downloaded from
   fiskheroes.fandom.com; only built-in suits are documented there.
2. **Model renders** (`assets/heroes/models/`, 24) — `tools/hero_previews_models.py`
   parses heropack renderer JS, resolves Tabula `.tbl` models (zip with model.json cubes
   + texture.png) and software-renders an orthographic front view. Two composition modes
   (identity / anchors) are tried; the tighter one wins. Handles both Tabula flavors
   (`parts` and `cubes`), drops inflated overlay shells (cube + cube_ol), chases
   `extend()` parents. Per-hero exceptions live in `OVERRIDES` inside the script
   (model name fragments, `{"vars": [...]}` or `[]` = deliberate skip).
3. **Texture front views** (`assets/heroes/game/`, 448) —
   `tools/hero_previews_game.py` composes head/torso/arms/legs from the skin-layout
   textures inside the mod jar and heropacks. If the first candidate texture fails the
   quality gate it retries with `loadTextures` singles and base+overlay combos (slim-arm
   and skin heroes). Unmasked suits get a **procedural default player head** drawn
   behind the mask (our own pixel art — never Mojang textures).

Run order matters: `hero_previews_models.py` → `hero_previews_game.py` →
`wiki_previews.py` (merge) → `fetch_descriptions.py` → `make_sheets.py` (QA contact
sheets, gitignored) → `tests/validate_data.py`. All except the merge need `--mc-root`
pointing at a local game install; the install is never committed.

### Quality gates (do not "fix" these away)

- The texture gate checks body ≥ 0.55 and arm/leg ≥ 0.2 coverage of the skin UV areas;
  **the head is deliberately not checked** — unmasked heroes have an empty head region
  by design (the player's head shows in game; we draw the procedural head instead).
  Re-adding a head check would reject ~100 good previews.
- Model-render gates reject empty, too-small and "scene-like" (army/portal) renders.
- `GAME_SKIP` in the game composer lists model-look heroes whose texture compose would
  be misleading (e.g. Hulk would show Bruce Banner).

## Wiki gotchas (solved in code, keep it that way)

- static.wikia CDN returns **403 on long User-Agents** — use exactly `Mozilla/5.0`.
- The CDN serves **WebP regardless of Accept**; responses are re-encoded through Pillow.
- Rapid request series get **rate-limited**; scripts retry with increasing backoff.
- Page "Doctor Octupus" contains a wiki typo (kept on purpose); the Savitar page
  redirects to The Rival, so a direct file mapping is used. Both live in `WIKI_PAGE`
  in `tools/wiki_previews.py`.
- TextExtracts is disabled on this wiki — use `action=parse&prop=wikitext`.

## Data updates

Site fetches `heroes_list.json` with `cache:'no-store'`; updating the catalog is
replacing that file (keep the exact hero key set:
`id, name, image, image_wiki, image_game, image_model, wiki`) plus, optionally:

```bash
python tools/generate_commands.py   # regenerate hero_atlas_commands.txt
python tests/validate_data.py       # must print PASSED
```

Hero `id` is always `packname:heroname`, lowercase, unique, prefix == pack key.

## Testing

- `python tests/validate_data.py` — counters, id format/uniqueness, per-pack counts,
  image files exist **and decode with PIL**, `aliases.json` and `descriptions.json`
  validity. Non-zero exit on any failure.
- Open `tests.html` in a browser (serve over HTTP, e.g. `python -m http.server 8123`) —
  it runs the full UI suite inside an iframe (rendering, filters, aliases search, copy,
  hero modal, image loading/decoding/pixelated, 8-language switching) and prints
  `PASSED: n/n` in the title. All checks must pass before committing UI changes.
- Telegram-only behavior (Mini App chrome, keyboard) is checked manually.

## Deployment / limits

Cloudflare Workers static assets deploy from `main` automatically (see
`docs/DEPLOYMENT.md`). Free-tier headroom is large but finite: ~20 000 files per deploy
(we ship ~530), 25 MB per file, repo files ≤ a few hundred KB. Convert previews to WebP
only if the asset tree ever grows substantially.

## Local development

```bash
python -m http.server 8123     # then open http://127.0.0.1:8123 (tests: /tests.html)
```

`file://` will not work — fetch() of the JSON needs HTTP.
